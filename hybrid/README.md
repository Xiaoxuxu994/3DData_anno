# 混合打标方案评测（线 H）

位姿来源 × 深度来源 × 尺度对齐 × 投票。复用线 E 已有的各方法输出，没有重新推理，只用 CPU。

- 代码：`code/hybrid/{hybrid.py, run_hybrid.py, report_hybrid.py, run_all.sh}`
- 结果：`outputs/hybrid/`
  - `tables.md` 是全部表格。
  - `ranking_A.csv` 是 40 个组合的排名。
  - `ranking_A_key.csv` 是 13 个关键组合之间的排名。
  - `*_per_clip.csv` 是逐段结果。
  - `retention_*.csv` 是置信度保留曲线。
  - `summary.json` 是汇总。
  - `raw/<kind>/<clip>.csv` 是逐段原始结果，可断点续跑。`raw/A_limit2.csv` 是冒烟测试的产物，可以忽略。

## 1. 组合的定义

规格写作 `H:<pose>+<depth>+<align>`，其余名字表示单一方法。

| 字段 | 取值 | 含义 |
|---|---|---|
| pose | vipe / spatialvid_metric / pi3x / da3 | 相机位姿与内参 K 都取自这个方法 |
| depth | pi3x / da3 / vggt_omega / vote3 / vote4 / own | 深度来源。vote3 = Pi3X、DA3、VGGT-Ω 三者逐像素取中位数；vote4 在 vote3 基础上再加 ViPE 自带深度 |
| align | raw / med / geo | 见第 2 节 |

一共 35 个混合组合和 5 个单一方法。评测分组如下：

- A 组 51 段（7-Scenes、TUM、Bonn、Sintel、KITTI，不含 ETH3D）。
- B 组 13 段（vKITTI2、TartanAir）。
- ScanNet++ 28 段，拆成 seen-25 和 unseen-3。
- C 组 wild 72 段。

指标与 `eval3d_bench.py` 完全一致，包括 ATE、尺度、FOV、深度三种口径、点云 F@5cm（pairs 对齐）、重投影 EPE 和失败率。另外新增两项：

- `pc_traj_fscore_5cm`：先用相机中心做 Sim3 对齐，再融合点云算 F@5cm。只有深度和平移处在同一个尺度时，这个值才会高，所以它检验的是位姿与深度的几何一致性。只在米制 GT 上计算。
- 置信度保留曲线：只保留最可信的 X% 像素时的深度误差。

点云和重投影都用**组合后的位姿 + 内参 + 深度**计算。

## 2. 尺度对齐的两种做法

- **(a) med**：每段一个尺度。在共同有效像素上取比值 s = median(位姿来源自带深度) / median(深度来源)。
- **(b) geo**：每段一个尺度。在位姿来源的相机下，把深度来源乘以 s 后，在帧对（gap 5、15，各 12 对，约 120 px 网格）之间互相投影，统计深度相对误差小于 5% 的内点比例，取使这个比例最大的 s。搜索分两步：先在 s_a·e^[-1.6,1.6] 范围内粗搜，再细搜。
  - 退回 (a) 的条件：视差 ＜ 0.01，或者峰值对比度 ＜ 0.01，或者最优值落在搜索边界上。
- **raw**：米制深度直接使用，不做对齐。只适用于 Pi3X 和 DA3。

### B 组（诊断）

前馈模型的 FOV 误差有 11–15°，换成 ViPE 的内参后这个问题直接消失。在 TartanAir 上，g5 EPE 的变化如下：

- ViPE 单独：37.9
- Pi3X 单独：27.3
- ViPE + Pi3X (geo)：**8.8**
- ViPE + Pi3X (med)：21.2

在 vKITTI2 上，ViPE 为 11.5，ViPE + Pi3X (med) 为 2.5，ViPE + vote3 (geo) 为 2.2。

在户外大尺度场景里，F@5cm 没有参考意义，以 EPE 为准。

### C 组 wild（无真值）

| ViPE + Pi3X (med) | 0.86 |

## 4. 对齐方法 (a) 与 (b) 的差异

- **(b) 估出的尺度和 (a) 的中位数比值约为 1.00**。|Δlog s| ＞ 0.1 的比例：A 组 22%，B 组 38–46%，ScanNet++ 14–21%，wild 35–42%。
- **退回 (a) 的比例**：ScanNet++ 0–4%，A 组 25–29%（KITTI 全部退回），wild 42–51%（driving 80–90%）。原因是前向行驶时尺度几乎不可辨识。
- **收益**：(b) 稳定降低重投影 EPE，这是它的优化目标。A 组 g20 从 11.1 降到 8.7，TartanAir g5 从 21 降到 8.8。A 组米制深度失败率也从 7.1% 降到 3.6%。
- **代价**：
  - A 组的米制 AbsRel 中位数略升（0.061 → 0.067）。
  - A 组 traj 点云 F 中位数下降（0.62 → 0.47）。下降集中在 TUM walking 和 Bonn 等动态场景，动态像素会拉偏一致性搜索。
  - 深度噪声大时 (b) 会偏向更大的尺度。最明显的例子是 `H:vipe+own+geo` 失败：A 组米制 AbsRel 0.25，ViPE 原值 0.11。
- **结论**：(b) 适合在静态、视差充足的片段上做精修。动态片段要先用 mask 把动态像素去掉，前向驾驶则直接用 (a)。另外，(a) 与 (b) 的分歧本身就是一个很好的 QC 信号。

## 5. 投票与置信度

- **投票的深度精度没有超过 Pi3X 单独**。seq AbsRel：A 组 vote3 0.047 对 Pi3X 0.046，ScanNet++ 0.026 对 0.023。Pi3X 明显强于其他成员，取中位数反而会稀释它。vote4（加入 ViPE 深度）在 A 组 seq 上更差，为 0.051。
- **投票的价值在于给出逐像素置信度**。按 spread 只保留 60% 像素时，seq AbsRel 下降 25–30%：A 组 0.047 → 0.033，ScanNet++ 0.027 → 0.021。保留到 40% 以下后基本饱和。
- **Pi3X 自带的 conf 是更好的像素排序器**。只保留 40% 像素时：
  - A 组从 0.046 降到 0.026（−43%）。
  - ScanNet++ 从 0.023 降到 0.010（−56%）。
  - DA3 自带 conf 次之。
- 米制 AbsRel 在过滤像素后几乎不变，因为误差主要来自整段的尺度。
- **建议**：像素置信度以 Pi3X conf 为主，同时把多模型 spread ＞ 0.05 的像素标为不确定，用来捕捉单个模型特有的失败。两者的组合效果还没有评测。

## 6. 推荐方案

**默认：ViPE 位姿和内参 + Pi3X 深度。** 尺度先用 (a) 中位数对齐。片段静态、视差充足、(b) 不退回且与 (a) 相差小于 10% 时，改用 (b)。逐像素置信度用 Pi3X conf，再叠加多模型 spread。

理由如下：

1. 在 13 个关键组合里排第 2，只比第 1 名差 0.14。第 1 名 SpatialVID + Pi3X 的米制尺度失败率高，在 ScanNet++ 和 B 组上也不如本方案，所以不推荐。米制深度这一项本方案排第 1。
2. 相对 ViPE 单独：
   - 位姿与 FOV 不变，A 组 FOV 失败率 19.6%，Pi3X 单独为 45%。
   - A 组米制 AbsRel 从 0.114 降到 0.061–0.067，深度失败率从 14.3% 降到 3.6–7.1%。
   - 点云 F 从 0.49 升到 0.80。
   - ScanNet++ unseen-3 上 g5 EPE 从 1.78 降到 0.54。
3. 相对 Pi3X 单独：
   - 保住了 ViPE 的内参和 FOV 精度，B 组 FOV 误差从 11–15° 降到 0.2°。
   - 前提是视差和尺度条件良好：ScanNet++ unseen-3 上 g5 EPE 1.79 → 0.54，TartanAir g5 EPE 27 → 8.8。
4. 不建议直接用 raw。米制深度单看还不错，但和位姿的尺度不一致：A 组 traj 点云 F 为 0.46，wild 自一致性为 0.73，都低于对齐后的结果。

需要注意的地方：

- **尺度失败率仍由轨迹决定**。A 组 ViPE 的尺度失败率（|s−1| ＞ 10%）为 28.6%，换深度修不了这个问题。下一步可以用 ViPE、Pi3X、DA3 三者的轨迹尺度做中位数投票。
- **driving 和 embodied（腕部相机）类别**：ViPE 位姿本身会失败，这些片段应该由 QC 层退回给 Pi3X 位姿，或者直接丢弃。
- **许可**：Pi3X、DA3-giant、VGGT-Ω 的权重都限非商业使用。如果要商用，深度来源需要换成可商用的模型。
