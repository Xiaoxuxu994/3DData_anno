读结果前：沙箱里没有 GLRMap 代码、GPU，也连不上你的服务器。第一阶段是 pycolmap 的降本复刻（640 px、60 帧、顺序匹配），比真实 GLRMap 更苛刻；VLM 判官是 Claude 不是 Qwen3-VL-32B。下面是线索和已经接通的管线，不是 GLRMap 的验收。

7 / 18简单片段通过第一阶段出口关口（复刻 v0a）
11 / 14有银参考的片段里，焦距与参考相差 > 10 %
190+项自动测试通过（含与原脚本逐项对拍）
1 · “简单”的网络视频，第一阶段并不容易过。复刻的第一阶段给出模型的 16 条里，7 条过关口；其余被 fx_fy_mismatch（fx 与 fy 差 > 10 %）、每图点数太少、平面对占比高或没出模型挡住。位姿本身大多是准的：与银参考比，11 / 14 条的 Sim(3) ATE ≤ 3.27 %。
2 · 主要风险是内参 K，不是轨迹。自由焦距的 PINHOLE 在前进镜头、远景航拍上焦距几乎不可观测：11 / 14 条的焦距与银参考差 > 10 %，其中 4 条还通过了关口（静默错误），v1c 的 K 容差（HFOV 13.2°，约 25 % 焦距）也不会拦。这和评估会话里的 KITTI / 无人机结论一致。
3 · 前端和关口是互补的两层。规则 + VLM 挡掉纯摇镜、静止、夜景、切镜、人群；开车类片段 VLM 判“可重建”，由路由送去 v1.3；第一阶段关口再兜住前端漏掉的退化（11 / 11 条对照被它 stop）。混入的 1 条淡水印（ia_telangana）规则和 VLM 都没看见。
4 · 管线接通了，并且按“查不出就拒绝”设计。路由 → 作业包 → worker（关口先于 RoMa / PDA）→ 收集 → 质检分级 → 合并 / 回退 v1.3，在真实片段上贯通；任何一环失败、缺证据、缺深度都变成拒绝，不会悄悄出标签。
5 · 没做、也做不了的。没有跑真实 GLRMap、RoMa、PDA、ViPE、Pi3X；证人质检只有接线测试。第二轮独立评审因预算停止。这些都在“下一步”里给了服务器上的执行清单。

管线front filter → router → GLRMap stage 1 + gate → dense → back QC → merge

  1. 前端筛选3DData_anno 原样：切镜、亮度模糊、OCR、光流、GeoCalib + VLM 判官，decide.py 出 pass / reject。
  2. 路由只让“静态场景 + 真视差”进 GLRMap；动态、旋转为主、驾驶、具身走 v1.3。自适应抽帧 60–120 帧。
  3. GLRMap 第一阶段COLMAP SIFT + 顺序匹配 + GLOMAP 全局建图。
  4. 出口关口注册率、点数、fx/fy、平面对、重投影、三角化角、K 证人分歧。stop 就不跑 RoMa / PDA，回退 v1.3。
  5. 稠密阶段RoMa v2 + Pi3X 先验 + PDA 深度（SfM 尺度）。
  6. 后端质检v1c 三项（对 ViPE 的轨迹、对 DA3 的深度、K 与 GeoCalib/Pi3X/DA3 的分歧）+ 旗标；查不出来一律拒绝。
  7. 分级与合并T1 / T2 用 GLR 标签；T3 或失败回退 v1.3 标签（v1c 通过才算）；再不行就拒绝。

蓝框 = 本次新增；其余是 3DData_anno 现有代码。

视差指数 = 旋转模型残差 / 光流（纯摇镜 ≤ 0.06，有真视差 ≥ 0.8）。焦距差取 fx、fy 中较差的一个。结局只在银参考成功时给出。

内参 K：焦距为什么不稳the dominant failure on web clips

银参考 = 另一次 SfM（每 6 帧、穷举匹配、SIMPLE_RADIAL、增量建图），不是真值，所以这里先问“两次独立重建的焦距是否一致”，再看 GeoCalib 站谁。

  • 航拍和前进镜头里焦距几乎不可观测：复刻的焦距常停在初值 1.2×长边附近，fx 与 fy 各自漂移，被 fx_fy_mismatch 拦下；或者通过关口但焦距偏差 20–80 %。
  • 银参考也会错（例如 mk_41574：复刻 0.81、GeoCalib 0.81、参考 1.15），所以单靠它不能判“静默错误”；这部分在 E 表里用三方对照单独列出，属于事后分析，不进预声明的结局统计。
  • 修法不在门槛上：评估会话的焦距扫描（E14）、K 先验初始化、固定 K、SIMPLE_PINHOLE，需要在服务器上用真实 GLRMap 做 Phase 0.2b 的消融，runbook 里写了通过线。

联调演示route → worker (gate) → collect → QC → merge on real clips

在真实片段上走完阶段 a（路由 + 作业包）→ b（worker：第一阶段复刻 + 真关口 + 稠密替身）→ c（收集、质检分级、合并）。稠密深度用稀疏点插值替身，证人用银参考重建替身，v1.3 一侧没有标签，所以没有回退标签可用。

限制：这些结论不能下what this does not show

  • 不能说“GLRMap 在简单网络视频上通过率是 X”。复刻是降本版（640 px、60 帧、顺序匹配、无引导）；真实 GLRMap 用全分辨率、约 100 帧、GPU SIFT。
  • 不能说“前端 + VLM 的召回是 X”。VLM 是 Claude 替身，片段 29 条，样本小。
  • 不能说“质检能抓住 GLR 的错”。证人质检只有接线测试，稠密深度和证人都是替身。
  • 银参考是第二次 SfM，不是真值；K 的对错没有地面真值。
